# ubi10-maddy

[maddy](https://maddy.email) on Red Hat UBI 10 micro: the upstream static (musl) release binary
`maddy`, checksum-verified, rebuilt on UBI updates.

A composable mail server: SMTP submission, queueing, DKIM signing and delivery to the
recipients' MX hosts or a smarthost, plus IMAP and local mailboxes.

Built from github.com/panda-coop/containers. Not affiliated with or supported by Red Hat or the
upstream project.

| Item | Value |
|---|---|
| Image | `quay.io/panda-coop/ubi10-maddy` |
| Upstream | `foxcpp/maddy`, version in `ARG VERSION` of the [Containerfile](Containerfile) |
| Download | `maddy-<version>-<arch>-linux-musl.tar.zst` from the GitHub release, arches `x86_64` and `aarch64` (static-pie) |
| Checksums | Upstream publishes no checksum file, only detached GPG signatures (`.sig`). The pinned sha256 values are GitHub's asset digests, checked against those signatures when pinned: signing subkey `CD76A6BB1D86CE4BC9C65BE5E943A49EE71E6169` of Max Mazurov's key `3197BBD95137E682A59717B434BB2007081396F4` (from `https://github.com/foxcpp.gpg`) |
| Base | `registry.access.redhat.com/ubi10/ubi-micro`, pinned by digest; the binary is static |
| Architectures | `amd64`, `arm64` (both checksums pinned; CI publishes `amd64`) |
| User | `1001:1001`, a fixed owner for the state volume (not `65534`: queued mail owned by `nobody` is readable by every other `nobody` process; upstream's image runs as root) |
| Licence | GPL-3.0-or-later (the source headers: "version 3 of the License, or (at your option) any later version"). The archive has no licence file: upstream `COPYING` and the configuration lexer's `LICENSE.APACHE` (Apache-2.0, code taken from Caddy) from the release tag, both sha256-pinned, in `/licenses/maddy/`. The `org.opencontainers.image.source` label points at that tag, `https://github.com/foxcpp/maddy/tree/v<version>` |
| CA bundle | `/etc/pki/ca-trust/extracted/pem/tls-ca-bundle.pem`, copied from UBI `ca-certificates` (ubi-micro has none), for TLS to MX hosts and smarthosts |

## Tags

| Tag | Example | Moves |
|---|---|---|
| `0.y.z-<epoch>` | `0.9.7-<epoch>` | never |
| `0.y.z` | `0.9.7` | on a UBI rebuild |
| `0.y` | `0.9` | on a patch release |
| `latest` | | on every release |

No `0` tag: for a 0.x version, `0.y` is the floating major. See
[ADR 0001](../docs/decisions/0001-image-tags-version-release-timestamp.md).

## Runtime

| Item | Value |
|---|---|
| Entrypoint | `/usr/bin/maddy`; arguments are a subcommand and its flags |
| Command | `run`, as upstream; `verify-config` checks the mounted configuration and exits |
| Configuration | None in the image: mount `/etc/maddy/maddy.conf` read-only (maddy's default path; `--config` or `MADDY_CONFIG` to move it). Without it maddy exits at start |
| State | `/var/lib/maddy`, the volume, mode `0700`, owner `1001:1001`: the queue, the message buffer, DKIM keys (`dkim_keys/`), the MTA-STS cache. maddy's default `state_dir`, and the working directory, so relative paths in the configuration land on the volume |
| Runtime directory | `/run/maddy`, owner `1001:1001`, maddy's default `runtime_dir` |
| Ports | `25/tcp`, `587/tcp` exposed (SMTP, submission); maddy listens only where the configuration says |
| Ports below 1024 | The process is not root, so listening on 25 or 587 needs `NET_BIND_SERVICE` (`--cap-add NET_BIND_SERVICE`, Quadlet `AddCapability=NET_BIND_SERVICE`) or `--sysctl net.ipv4.ip_unprivileged_port_start=25`; both checked under rootless Podman. A listener on 1024 or above needs neither |
| Bind mount | The host directory must be owned by `1001` inside the user namespace: `Volume=/srv/maddy:/var/lib/maddy:Z,U` |
| Logs | stderr, as upstream's `--log` default |

maddy has no health endpoint; `podman exec maddy maddy verify-config` re-checks the configuration
against the running image.

## Example: outbound relay

A minimal `/etc/maddy/maddy.conf`: accept mail from `example.org` senders on 587, sign it with
DKIM, queue it on the volume and deliver it to the recipients' MX hosts. Nothing but the sender
domain is checked on this listener, so it must be reachable only from trusted clients.

```text
hostname relay.example.org
tls off

smtp tcp://0.0.0.0:587 {
    source example.org {
        modify {
            dkim example.org example.org default
        }
        deliver_to &remote_queue
    }
    default_source {
        reject 501 5.1.8 "Sender domain not relayed"
    }
}

target.queue remote_queue {
    target &outbound_delivery
    autogenerated_msg_domain example.org
    bounce {
        reject 550 5.0.0 "Bounces are not delivered"
    }
}

target.remote outbound_delivery {
}
```

```sh
podman volume create maddy-state
podman run -d --name maddy --network mail --cap-add NET_BIND_SERVICE \
  -v ./maddy.conf:/etc/maddy/maddy.conf:ro,Z \
  -v maddy-state:/var/lib/maddy \
  quay.io/panda-coop/ubi10-maddy:0.9
```

On the first start maddy writes the DKIM key to `/var/lib/maddy/dkim_keys/`; the
`example.org_default.dns` file there is the TXT record for `default._domainkey.example.org`. To
send through a provider instead of the MX hosts, replace `target.remote` with a `target.smtp`
block (`targets tls://<host>:465`, `auth plain {env:USER} {env:PASSWORD}`) and point the queue at
it; maddy refuses to start with an unused block. A `target.smtp` to a plaintext server needs
`starttls no`.

## Local build

```sh
task build IMAGE=maddy     # localhost/ubi10-maddy:dev
task run IMAGE=maddy -- version
task inspect IMAGE=maddy
```

A version bump changes `ARG VERSION` and both `ARG SHA256_*` architecture values together.
Download both archives and their `.sig` files from the release
(`gh release download v<version> -R foxcpp/maddy -p '*-linux-musl.tar.zst*'`), check them with
`gpg --verify <archive>.sig <archive>` against `https://github.com/foxcpp.gpg`, and pin the
`sha256sum` of each archive (equal to the `digest` GitHub lists for the asset).
`SHA256_COPYING` and `SHA256_LICENSE_APACHE` change only if upstream changes those texts. A
stale checksum fails the build.
